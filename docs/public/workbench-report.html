A portable relationship and selection model

A branch is a relationship, not a renderer trick.

  • Relationships come from the API. Message-ID, In-Reply-To, and References establish actual parent links; input order and neighboring rows do not.
  • Focus, expansion, and selection are separate. A collapsed branch keeps selected descendants. Mixed checkboxes describe partly selected groups.
  • Selection is an explicit snapshot. A branch selects loaded member IDs, including hidden descendants. New replies remain unselected. Query-scope changes clear selection; sorting and client changes preserve it.
  • Coverage stays visible. Unknown children and missing parents are represented explicitly. A complete loaded group is not a promise about future messages.

Thread fixtures are loaded through GET /api/mail/threads. Branch membership is also verified through the revision-guarded selection API.

Unavailable doesn’t mean empty.

Working reconciliation function

Lose a source, and its last loaded section remains visible in that query—including its reply relationships and selected descendants. Confirm the source is genuinely empty, and the old rows disappear. Counts are marked incomplete during an outage.
